# RAG Document Query Engine — Backend

A self-hosted backend for querying your own documents with natural language. Upload PDF, Word (.docx), HTML, and Markdown files; ask questions in plain English; get answers generated by an LLM with source citations pointing at the exact passages used.

Built for a single personal user running locally — no accounts, no tenants, no extra infrastructure beyond two hosted APIs. The frontend lives in a sibling `frontend/` repository and talks to this backend over REST.

## Description

The engine works in two phases:

1. **Ingestion** — you upload a document; a background job parses it (per format), splits it into structure-aware chunks, embeds each chunk, and indexes it for hybrid search.
2. **Query** — you ask a question; the engine retrieves the most relevant chunks via hybrid retrieval (keyword + vector), reranks them, and asks an LLM to answer using only those chunks. The response includes the answer plus the source chunks it was drawn from.

Everything runs locally; hosted services provide the AI capabilities:

| Service | Used for | Model / index |
|---|---|---|
| **DeepSeek API** | chat generation (answer synthesis) | `deepseek-v4-flash`, non-thinking |
| **Pinecone** | vector storage + hosted inference | `llama-text-embed-v2` (1024-dim) embeddings, `bge-reranker-v2-m3` reranking |
| **SQLite + FTS5** | metadata, chunks, jobs, BM25 keyword search | local file at `data/engine.db` |

No local model files, no torch, no self-hosted infrastructure.

## Features

- **Ingest PDF, docx, HTML, and Markdown** via background jobs with pollable progress (parse → chunk → embed → index).
- **Hybrid retrieval**: BM25 (SQLite FTS5) fused with vector similarity (Pinecone) via Reciprocal Rank Fusion, then cross-encoder reranking.
- **Citable answers**: every response returns the top-3 source chunks (`chunk_id`, `doc_id`, `doc_name`, `excerpt`, `score`) alongside the generated answer.
- **Document management**: list with ingestion status, detail view, delete (vectors + chunks + original file), and re-index.
- **REST API** served by FastAPI for the sibling frontend.
- **Stateless queries** — no conversation history in v1.

## Prerequisites

- **Python 3.14** (an existing `.venv` is expected in the repo root).
- **A Pinecone account** with a serverless index (AWS `us-east-1`, dimension 1024, cosine) **pre-created by you** — the backend does not create it. Index name goes in `PINECONE_INDEX`.
- **A DeepSeek API key** (OpenAI-compatible endpoint).

## Setup

```powershell
# 1. Install dependencies into the existing virtualenv
.venv\Scripts\pip install -r requirements.txt

# 2. Create your environment file
Copy-Item .env.example .env
```

Fill in `.env` (never commit it):

```env
PINECONE_API_KEY=your-pinecone-key
PINECONE_INDEX=your-index-name
DEEPSEEK_API_KEY=your-deepseek-key
```

The database schema and `data/` directories are created automatically on first start; no manual migration step is needed.

## Start the server

```powershell
.venv\Scripts\uvicorn app.main:app --reload
```

The API is then available at `http://localhost:8000`:

- Interactive docs (Swagger UI): <http://localhost:8000/docs>
- OpenAPI schema: <http://localhost:8000/openapi.json>
- Liveness check: `GET /health` → `{"status": "ok"}`

## Try it

```powershell
# Upload a document (accepted: .pdf, .docx, .html, .htm, .md)
curl -X POST http://localhost:8000/documents -F "file=@notes.md"

# Poll the job until it succeeds
curl http://localhost:8000/jobs/<job_id>

# Ask a question
curl -X POST http://localhost:8000/queries -H "Content-Type: application/json" -d '{"question": "What did I write about X?"}'
```

## Configuration

All settings live in `.env` / `app/config.py` (`pydantic-settings`):

| Setting | Default | Description |
|---|---|---|
| `PINECONE_API_KEY` | — | Pinecone API key (required) |
| `PINECONE_INDEX` | — | Pre-created Pinecone index name (required) |
| `DEEPSEEK_API_KEY` | — | DeepSeek API key (required) |
| `DEEPSEEK_MODEL` | `deepseek-v4-flash` | Chat model |
| `DEEPSEEK_BASE_URL` | `https://api.deepseek.com` | OpenAI-compatible base URL |
| `MAX_UPLOAD_SIZE_MB` | `50` | Upload size limit |
| `JOB_MAX_WORKERS` | `2` | Ingestion thread-pool concurrency |
| `UPLOAD_DIR` | `data/uploads` | Where originals are stored |
| `DATABASE_PATH` | `data/engine.db` | SQLite database file |

## API summary

| Endpoint | Method | Purpose |
|---|---|---|
| `/health` | GET | Liveness check |
| `/documents` | POST | Upload a document (background ingestion) |
| `/documents` | GET | List documents, newest first |
| `/documents/{id}` | GET | Document detail + chunk count |
| `/documents/{id}` | DELETE | Delete vectors, chunks, and the original file |
| `/documents/{id}/reindex` | POST | Re-run ingestion on the stored original |
| `/jobs/{id}` | GET | Job progress (stage, chunk counts, error) |
| `/queries` | POST | Ask a question; returns answer + sources |
